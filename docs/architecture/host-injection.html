Principles

  • Use the least invasive insertion mechanism that delivers exact text.
  • Prefer semantic text APIs over synthetic key events.
  • Keep terminal submission explicit: never append Enter by default.

GUI Targets

Preferred insertion order for GUI targets on Ubuntu GNOME Wayland:

  1. AT-SPI editable text insertion or replacement
  2. Clipboard-assisted paste with clipboard restoration
  3. Keyboard simulation fallback

AT-SPI First

AT-SPI exposes direct editable text operations without the focus and timing races of synthetic keystrokes. It is the preferred target for browser editors, GTK apps, Electron apps, and IDEs that expose accessibility trees.

Clipboard Second

Clipboard paste works across most GUI applications and avoids keyboard layout issues. Implementations must snapshot and restore prior clipboard text when requested.

Keyboard Simulation Last

Wayland intentionally restricts unrestricted input event injection. Tools such as ydotool and wtype remain fallbacks rather than the primary contract.

Terminal and TUI Targets

Preferred insertion order for terminal and TUI targets:

  1. Bracketed paste payloads (\x1b[200~...\x1b[201~)
  2. Terminal-specific send-text adapters (tmux, WezTerm, Kitty)
  3. Clipboard paste fallback when explicitly requested

Default Safety Rule

Terminal injection must not execute commands automatically. Post-insert submission requires an explicit opt-in flag (auto_submit=true) on the request.

Adapter Extensions

Additional host adapters (direct Kitty socket remote control, Neovim RPC, or native AT-SPI text writers) plug into the same InjectionPlan contract rather than introducing parallel target types.
