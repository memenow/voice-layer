Goals

VoiceLayer handles two primary workflows through one shared domain model:

  • Dictation: low-latency speech-to-text insertion into the focused GUI or terminal target.
  • Composition: converting spoken intent or existing text into a structured preview before insertion (compose, rewrite, and translate).

Runtime Topology

+--------+   +--------------+      HTTP/JSON over UDS      +-------------+
|  vl    |   |  vl-desktop  | <--------------------------> | voicelayerd |
| (CLI)  |   |  (iced GUI)  |                              +-------------+
+--------+   +--------------+                                     |
                                                                  | JSON-RPC 2.0 over stdio
                                                                  v
                                                         +-------------------+
                                                         | voicelayer_worker |
                                                         +-------------------+

vl and vl-desktop share the same /v1 Unix domain socket, session table, and Server-Sent Events stream. vl-desktop also registers the global shortcut voicelayer.dictation_toggle (via XDG GlobalShortcuts on Linux or Carbon hotkeys on macOS) to trigger the same start/stop API calls as its UI controls.

Component Responsibilities

Rust Workspace

  • voicelayer-core: domain types, typed config parsing, and shared UDS HTTP/SSE client.
  • voicelayerd: long-running daemon, cpal audio capture, segmented dictation orchestration, /v1 HTTP API, and worker process supervision.
  • voicelayer-cli (vl): operator CLI, config management, terminal push-to-talk TUI, and terminal paste adapters.
  • voicelayer-desktop (vl-desktop): multi-window iced GUI, capture HUD overlay, global hotkeys, and optional system tray.
  • voicelayer-ui: shared color, spacing, and typography tokens.

Python Worker

  • python/voicelayer_worker: JSON-RPC server, provider registry, unified Silero VAD pre-pass, WAV splitting/stitching, and backend drivers for whisper.cpp, MiMo-V2.5-ASR, Qwen3-ASR-1.7B, and OpenAI-compatible LLMs.

Domain Objects

The public contract types shared across Rust, Python, and OpenAPI are:

  • CaptureSession
  • TranscriptChunk
  • CompositionReceipt
  • PreviewArtifact
  • InjectionPlan and InjectTarget
  • ProviderDescriptor
  • LanguageProfile and LanguageStrategy
  • SegmentationMode (one_shot, fixed, vad_gated)

Global hotkey bindings and CLI keybindings stay client-side rather than becoming part of the daemon API schema.

Transport Boundaries

  • External control plane: HTTP/1.1 with JSON payloads over a Unix domain socket, documented in openapi/voicelayerd.v1.yaml.
  • Live event feed: Server-Sent Events at GET /v1/events/stream.
  • Rust-to-Python bridge: line-delimited JSON-RPC 2.0 over stdio, launched through the repository's uv environment. See Python Worker Protocol.

Configuration Precedence

The vl dictation foreground-ptt command resolves options in three layers (highest precedence first):

  1. CLI flags passed directly on the command line (such as --language en, --key f9, or --default-stop-action inject).
  2. TOML config file managed with vl config set <key> <value> at the path printed by vl config path (typically ~/.config/voicelayer/config.toml).
  3. Struct defaults from ForegroundPttConfig::default.

Supported vl config set keys:

foreground_ptt.language                    (BCP-47 tag; "none" clears)
foreground_ptt.translate_to_english        bool
foreground_ptt.keep_audio                  bool
foreground_ptt.key                         space | enter | tab | f8 | f9 | f10
foreground_ptt.tmux_target_pane            tmux pane id (%N); "none" clears
foreground_ptt.wezterm_target_pane_id      wezterm pane id; "none" clears
foreground_ptt.kitty_match                 kitten match expression; "none" clears
foreground_ptt.copy_on_stop                bool
foreground_ptt.default_stop_action         none | copy | inject | save
foreground_ptt.restore_clipboard_on_exit   bool
foreground_ptt.save_dir                    directory path; "none" clears
foreground_ptt.provider_id                 whisper_cpp | mimo_v2_5_asr | qwen3_asr_1_7b; "none" clears

Boolean keys accept true/false, 1/0, yes/no, or on/off.

Audio Capture

voicelayerd captures microphone audio in process via cpal (PipeWire ALSA shim on Linux, CoreAudio on macOS), avoiding external recorder subprocesses. A dedicated capture thread converts incoming audio to mono f32 samples in a continuous per-session buffer. WAV segments are sliced directly from that buffer and resampled to 16 kHz mono PCM, so segmented capture does not drop audio at chunk boundaries.

When live dictation stops or a segment flushes, the daemon sends the WAV file to the Python worker's transcribe RPC, which routes to the requested provider_id (or defaults to whisper-server with whisper-cli fallback).

Dictation Segmentation

StartDictationRequest.segmentation selects how live dictation partitions audio:

  • {"mode": "one_shot"} (default): captures continuously from start to stop and transcribes the full WAV once on stop.
  • {"mode": "fixed", "segment_secs": N}: slices the capture buffer every N seconds and transcribes each finalized chunk in the background while recording continues. Stop waits for pending tasks and returns the joined transcript. With keep_audio=true, DictationCaptureResult.audio_file points at the per-session segment directory under $XDG_RUNTIME_DIR/voicelayer/dictation/<session_id>/.
  • {"mode": "vad_gated", "probe_secs": P, "max_segment_secs": M, "silence_gap_probes": G}: slices short probes every P seconds and classifies each probe via the worker's segment_probe RPC (Silero VAD). Speech probes accumulate and flush as a single WAV unit when G consecutive silent probes arrive (default 1) or buffered duration reaches M seconds. If VAD is unavailable, probes fall back to a speech verdict so audio is never silently dropped.

Live sessions emit typed events on GET /v1/events/stream:

  • dictation.session_created, dictation.listening, dictation.transcribing: core lifecycle transitions.
  • dictation.segmented_started and dictation.vad_gated_started: emitted when a segmented task starts.
  • dictation.segment_recorded, dictation.segment_transcribed, and dictation.segment_transcribe_failed: fixed-mode and per-unit transcription progress and errors.
  • dictation.probe_analyzed, dictation.speech_unit_flushed, and dictation.speech_unit_transcribed: VAD-gated probe classification and unit flush progress.
  • dictation.completed and dictation.failed: terminal session outcomes.

Bounded single-clip capture (POST /v1/dictation/capture) and direct file transcription (POST /v1/transcriptions) always run a single transcribe call using the same provider routing.

Optional Silero VAD Pre-pass

When VOICELAYER_WHISPER_VAD_ENABLED=true and VOICELAYER_WHISPER_VAD_MODEL_PATH points to a Silero VAD v4 or v5 ONNX model, python/voicelayer_worker/pipeline.py runs one shared VAD pre-pass before dispatching to any ASR backend (whisper.cpp, MiMo-V2.5-ASR, or Qwen3-ASR-1.7B). Non-speech regions are trimmed into a temporary 16-bit mono WAV, and pure-silence clips short-circuit to an empty transcript before model inference. Temporary WAV sidecars are removed in a finally block.

Runtime dependencies (numpy, onnxruntime) live in the optional vad extra. If imports or VAD execution fail, the worker annotates the result notes and falls back to the original WAV. See ASR Providers for tuning options.
