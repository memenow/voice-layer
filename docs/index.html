VoiceLayer

VoiceLayer is a local-first voice composition layer for Ubuntu desktop workflows. It packages low-latency dictation, structured text composition, rewriting, and translation behind a single daemon, a CLI / TUI, an optional GUI shell, and a small set of host adapters that route the result into whichever editor, browser, IDE, or terminal application currently has focus.

Scope. VoiceLayer targets browser text areas, document and IDE editors, terminal multiplexers (tmux, WezTerm, Kitty), and drafting workflows that benefit from a preview-then-insert step. It is not a traditional IME candidate window, a subtitle-only transcriber, a browser-only extension, or a cloud-only voice assistant.

What ships today

  • Rust workspace with voicelayer-core (domain), voicelayerd (daemon and /v1 HTTP API over a Unix domain socket), vl (operator CLI / TUI), and vl-desktop (interactive iced GUI shell that shares the daemon socket).
  • Live dictation with one-shot, fixed-duration segmented, and silero-vad gated capture; per-session ASR provider routing; per-segment Server-Sent Events on /v1/events/stream.
  • Optional silero-vad pre-pass that trims non-speech inside the Python worker before transcription, applied uniformly across whisper.cpp, MiMo-V2.5-ASR, and Qwen3-ASR-1.7B.
  • Real ASR through whisper.cpp: one-shot whisper-cli with an opt-in persistent whisper-server endpoint for warm-model reuse and lazy autostart.
  • Optional GPU ASR providers, opt-in per-request via provider_id: Xiaomi MiMo-V2.5-ASR for multilingual / quality priority workloads; Alibaba Qwen3-ASR-1.7B for Apache-2.0 30-language coverage including Mandarin and Cantonese.
  • Real composition / rewrite / translation through an OpenAI-compatible chat completion endpoint, with optional llama-server autostart for local endpoints.
  • Persistent Rust ↔ Python stdio JSON-RPC bridge — the daemon keeps a single Python worker subprocess alive across every request so multi-GB GPU model loads pay their cold start only once per daemon lifetime.
  • systemd user units for voicelayerd and the optional voicelayer-whisper-server, plus a scripts/install.sh one-shot installer.
  • vl doctor surfaces recorder diagnostics, whisper mode (cli / server / unconfigured), LLM reachability, GlobalShortcuts portal status, and systemd unit state.

Quick start

Build the workspace, sync the Python environment, and start the daemon from the repository root:

cargo build --release --bin vl --bin vl-desktop --bin voicelayerd
uv sync --group dev
cargo run -p vl -- daemon run --project-root "$(pwd)"

Inspect the running environment, providers, and supported transcript provider ids:

cargo run -p vl -- doctor
cargo run -p vl -- providers

Record a short clip and transcribe it through the configured ASR backend:

cargo run -p vl -- record-transcribe --duration-seconds 8 --language auto

For longer sessions, drive the daemon's live dictation control plane:

cargo run -p vl -- dictation start --backend pipewire --language auto
cargo run -p vl -- dictation stop <session-id>

Open a terminal-local push-to-talk panel with hold-to-record, scrolling transcript review, clipboard restore, and optional tmux / WezTerm / Kitty targets:

cargo run -p vl -- dictation foreground-ptt --backend pipewire --language auto

Verification chain

Every change must pass the same chain before merge — see Development Guide for the full discussion:

cargo fmt --all
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all
uv sync --group dev
uv run ruff check python tests/python
uv run ruff format --check python tests/python
uv run pytest -q tests/python
