Default Backend: whisper.cpp

The default ASR backend targets whisper.cpp, supporting both one-shot whisper-cli invocations and persistent whisper-server HTTP endpoints. whisper-cli accepts flac, mp3, ogg, and wav files.

Build whisper.cpp locally:

git clone https://github.com/ggml-org/whisper.cpp.git
cd whisper.cpp
cmake -B build
cmake --build build -j --config Release
./build/bin/whisper-cli -m models/ggml-base.en.bin -f samples/jfk.wav

whisper.cpp Environment Variables

One-shot whisper-cli configuration:

VOICELAYER_WHISPER_BIN=whisper-cli
VOICELAYER_WHISPER_MODEL_PATH=/absolute/path/to/ggml-base.en.bin
VOICELAYER_WHISPER_TIMEOUT_SECONDS=300
VOICELAYER_WHISPER_NO_GPU=false
VOICELAYER_WHISPER_ARGS=

VOICELAYER_WHISPER_MODEL_PATH is required for the whisper-cli path.

Persistent whisper-server

Spawning whisper-cli pays model initialization latency on every transcription call. A persistent whisper-server keeps the ggml model memory-mapped across calls, which cuts per-segment latency during segmented dictation. When configured and reachable, the worker selects whisper-server first and falls back to whisper-cli otherwise.

VOICELAYER_WHISPER_SERVER_HOST=127.0.0.1
VOICELAYER_WHISPER_SERVER_PORT=8188
VOICELAYER_WHISPER_SERVER_TIMEOUT_SECONDS=60
VOICELAYER_WHISPER_SERVER_AUTO_START=false
VOICELAYER_WHISPER_SERVER_BIN=/abs/path/to/whisper-server
VOICELAYER_WHISPER_SERVER_ARGS=-t 4
VOICELAYER_WHISPER_SERVER_LAUNCH_TIMEOUT_SECONDS=30
VOICELAYER_WHISPER_SERVER_POLL_INTERVAL_SECONDS=0.5

When VOICELAYER_WHISPER_SERVER_AUTO_START=true, the worker launches whisper-server against VOICELAYER_WHISPER_MODEL_PATH and polls GET / until ready (writing PID and log state under $XDG_RUNTIME_DIR/voicelayer/providers/). You can also run whisper-server directly or in Docker:

# Host binary:
whisper-server -m /path/to/ggml-base.en.bin --host 127.0.0.1 --port 8188 -t 4

# Docker:
docker run -d --name voicelayer-whisper-server \
  -v /path/to/ggml-base.en.bin:/model.bin:ro \
  -p 127.0.0.1:8188:8080 \
  --entrypoint whisper-server \
  ghcr.io/ggml-org/whisper.cpp:main \
  -m /model.bin --host 0.0.0.0 --port 8080 -t 4

Point VoiceLayer at the running server:

export VOICELAYER_WHISPER_SERVER_HOST=127.0.0.1
export VOICELAYER_WHISPER_SERVER_PORT=8188

The worker sends multipart POST /inference requests with file, language, translate, and response_format=json.

Example Source Workflow

export VOICELAYER_PROJECT_ROOT="$(pwd)"
export VOICELAYER_WHISPER_BIN="/path/to/whisper-cli"
export VOICELAYER_WHISPER_MODEL_PATH="/path/to/ggml-base.en.bin"

cargo run -p voicelayer-cli -- doctor
cargo run -p voicelayer-cli -- transcribe-file /path/to/sample.wav --language auto
cargo run -p voicelayer-cli -- record-transcribe --duration-seconds 8 --language auto

Audio Capture and Silero VAD

Microphone capture runs in process inside voicelayerd via cpal (PipeWire ALSA shim on Linux, CoreAudio on macOS). Finished WAV clips are sent to the worker's transcribe RPC.

Optional Silero VAD Pre-pass

python/voicelayer_worker/pipeline.py can run a single Silero VAD pre-pass before dispatching to any ASR backend (whisper.cpp, MiMo-V2.5-ASR, or Qwen3-ASR-1.7B). When enabled, non-speech spans are stripped into a temporary 16-bit mono WAV, and clips with no detected speech short-circuit to an empty transcript without invoking the ASR model. That avoids wasting inference time and prevents causal LM backends from hallucinating text on silence.

Install the optional vad extra (numpy and onnxruntime) and download a Silero VAD v4 or v5 ONNX model:

uv sync --extra vad
curl -L -o /abs/path/to/silero_vad.onnx \
  https://github.com/snakers4/silero-vad/raw/master/src/silero_vad/data/silero_vad.onnx

Environment variables (the WHISPER_VAD_ prefix applies to all ASR backends):

VOICELAYER_WHISPER_VAD_ENABLED=true
VOICELAYER_WHISPER_VAD_MODEL_PATH=/abs/path/to/silero_vad.onnx
VOICELAYER_WHISPER_VAD_THRESHOLD=0.5
VOICELAYER_WHISPER_VAD_MIN_SPEECH_MS=250
VOICELAYER_WHISPER_VAD_MIN_SILENCE_MS=100
VOICELAYER_WHISPER_VAD_SPEECH_PAD_MS=30
VOICELAYER_WHISPER_VAD_MAX_SEGMENT_SECS=30
VOICELAYER_WHISPER_VAD_SAMPLE_RATE=16000

Supported sample rates are 16000 Hz and 8000 Hz. If onnxruntime or numpy cannot be imported at runtime, the worker records a note and falls back to transcribing the raw WAV.

VAD-Gated Live Dictation

In vad_gated mode, voicelayerd slices short probes every probe_secs seconds and classifies each probe through the worker's segment_probe RPC. Speech probes accumulate until silence_gap_probes consecutive silent probes arrive (default 1) or buffered audio reaches max_segment_secs, then flush as one speech unit to transcribe.

export VOICELAYER_WHISPER_VAD_ENABLED=true
export VOICELAYER_WHISPER_VAD_MODEL_PATH=/abs/path/to/silero_vad.onnx

cargo run -p voicelayerd
cargo run -p voicelayer-cli -- dictation start \
  --mode vad-gated --probe-secs 2 --max-segment-secs 30 \
  --language auto
cargo run -p voicelayer-cli -- dictation stop <session-id>

For unattended smoke tests, add --duration-seconds N so the CLI auto-stops and prints the final DictationCaptureResult:

cargo run -p voicelayer-cli -- dictation start \
  --mode vad-gated --probe-secs 2 --max-segment-secs 30 \
  --duration-seconds 12 --language auto

If segment_probe fails or VAD is unconfigured, each probe falls back to a speech verdict so audio is never silently discarded (making max_segment_secs the sole flush boundary).

MiMo-V2.5-ASR (Optional CUDA Provider)

VoiceLayer supports Xiaomi MiMo-V2.5-ASR as an opt-in backend selected via provider_id = "mimo_v2_5_asr".

Characteristics and Constraints

  • Multilingual coverage: Mandarin, Cantonese, Wu, Minnan, Sichuanese, English, and Chinese-English code-switching.
  • CUDA-only runtime: upstream audio tokenizer imports flash_attn.flash_attn_varlen_func unconditionally.
  • Requires ~16 GB VRAM at bf16 (~15 GB weights on disk).
  • No streaming, partial hypotheses, or word timestamps.
  • Inputs longer than VOICELAYER_MIMO_LONG_AUDIO_SPLIT_SECONDS (default 180 s) are split into WAV chunks in python/voicelayer_worker/audio.py to avoid upstream decoder repetition on long audio.
  • Cold model load takes tens of seconds once per worker lifetime; subsequent calls reuse the cached instance inside python/voicelayer_worker/providers/mimo_asr.py.

Setup

# 1. Install PyTorch matching your CUDA toolkit (cu128 for Blackwell, cu126/cu124 for Hopper/Ada).
#    Pin torch 2.10 while prebuilt flash-attn wheels target torch 2.10 + cp312.
uv sync --group dev
uv pip install --index-url https://download.pytorch.org/whl/cu128 \
  "torch==2.10.0" "torchaudio==2.10.0"

# 2. Install the mimo extra dependencies.
uv pip install -e ".[mimo]"

# 3. Install the matching prebuilt flash-attn wheel (avoids a long nvcc source build).
uv pip install \
  "https://github.com/Dao-AILab/flash-attention/releases/download/v2.8.1/flash_attn-2.8.1+cu12torch2.10cxx11abiTRUE-cp312-cp312-linux_x86_64.whl"

# 4. Download both the LM weights and mandatory audio tokenizer.
hf download XiaomiMiMo/MiMo-V2.5-ASR \
  --local-dir ~/.cache/voicelayer/models/mimo-v2.5-asr
hf download XiaomiMiMo/MiMo-Audio-Tokenizer \
  --local-dir ~/.cache/voicelayer/models/mimo-audio-tokenizer

# 5. Clone the upstream repository for the MimoAudio wrapper.
git clone https://github.com/XiaomiMiMo/MiMo-V2.5-ASR.git \
  ~/.cache/voicelayer/sources/MiMo-V2.5-ASR

Environment Variables

VOICELAYER_MIMO_MODEL_PATH=/abs/path/to/MiMo-V2.5-ASR
VOICELAYER_MIMO_TOKENIZER_PATH=/abs/path/to/MiMo-Audio-Tokenizer
VOICELAYER_MIMO_REPO_PATH=/abs/path/to/MiMo-V2.5-ASR-source-checkout
VOICELAYER_MIMO_DEVICE=cuda:0
VOICELAYER_MIMO_AUDIO_TAG=
VOICELAYER_MIMO_TIMEOUT_SECONDS=600
VOICELAYER_MIMO_LONG_AUDIO_SPLIT_SECONDS=180
VOICELAYER_MIMO_ARGS=

VOICELAYER_MIMO_MODEL_PATH and VOICELAYER_MIMO_TOKENIZER_PATH are required. Leave VOICELAYER_MIMO_AUDIO_TAG empty for automatic language detection or set <chinese> / <english>; request language tags (zh, yue, en, etc.) are mapped automatically.

Selecting MiMo Per Request or Session

SOCKET="${XDG_RUNTIME_DIR:-/run/user/$UID}/voicelayer/daemon.sock"
curl --unix-socket "$SOCKET" -s -X POST http://d/v1/transcriptions \
  -H 'content-type: application/json' \
  -d '{"audio_file":"/abs/path/sample-zh.wav","provider_id":"mimo_v2_5_asr","language":"zh"}'

cargo run -p voicelayer-cli -- dictation start --mode fixed --segment-secs 8 --provider-id mimo_v2_5_asr
cargo run -p voicelayer-cli -- record-transcribe --duration-seconds 8 --provider-id mimo_v2_5_asr
cargo run -p voicelayer-cli -- dictation foreground-ptt --provider-id mimo_v2_5_asr
vl config set foreground_ptt.provider_id mimo_v2_5_asr

Unrecognized provider_id values fail explicitly with provider_unavailable rather than falling back to whisper.

Qwen3-ASR-1.7B (Optional Apache-2.0 Provider)

VoiceLayer supports Alibaba Qwen3-ASR-1.7B as an opt-in Apache-2.0 backend selected via provider_id = "qwen3_asr_1_7b".

Characteristics and Constraints

  • Covers 30 languages including Mandarin, Cantonese, English, Japanese, Korean, European, and Southeast Asian languages.
  • Apache-2.0 weights (~4.7 GB on disk, ~6 GB VRAM at bf16) with no flash-attn dependency.
  • Transcription only: no streaming, no word timestamps, and translate_to_english=true is rejected by the daemon.
  • CPU inference works but runs roughly 10-30x slower than real time.

Setup

uv sync --group dev
uv pip install --index-url https://download.pytorch.org/whl/cu128 \
  "torch>=2.7,<3.0" "torchaudio>=2.7,<3.0"
uv pip install -e ".[qwen3-asr]"
hf download Qwen/Qwen3-ASR-1.7B \
  --local-dir ~/.cache/voicelayer/models/qwen3-asr-1.7b

The qwen3-asr and mimo extras pin different transformers versions. Install only one extra per virtual environment.

Environment Variables

VOICELAYER_QWEN3_ASR_MODEL_PATH=/abs/path/to/qwen3-asr-1.7b
VOICELAYER_QWEN3_ASR_DEVICE=cuda:0
VOICELAYER_QWEN3_ASR_TORCH_DTYPE=bfloat16
VOICELAYER_QWEN3_ASR_TIMEOUT_SECONDS=600
VOICELAYER_QWEN3_ASR_LONG_AUDIO_SPLIT_SECONDS=0
VOICELAYER_QWEN3_ASR_ARGS=

VOICELAYER_QWEN3_ASR_MODEL_PATH is required. VOICELAYER_QWEN3_ASR_DTYPE is accepted as a legacy alias for VOICELAYER_QWEN3_ASR_TORCH_DTYPE (use float16 on pre-Ampere GPUs or float32 for debugging). VOICELAYER_QWEN3_ASR_LONG_AUDIO_SPLIT_SECONDS defaults to 0 because qwen-asr chunks long audio internally; set a positive value to enforce worker-side WAV chunking. VOICELAYER_QWEN3_ASR_ARGS is reserved for future upstream arguments.

Selecting Qwen3-ASR Per Request or Session

SOCKET="${XDG_RUNTIME_DIR:-/run/user/$UID}/voicelayer/daemon.sock"
curl --unix-socket "$SOCKET" -s -X POST http://d/v1/transcriptions \
  -H 'content-type: application/json' \
  -d '{"audio_file":"/abs/path/sample-zh.wav","provider_id":"qwen3_asr_1_7b","language":"zh"}'

cargo run -p voicelayer-cli -- dictation start --mode fixed --segment-secs 8 --provider-id qwen3_asr_1_7b
cargo run -p voicelayer-cli -- record-transcribe --duration-seconds 8 --provider-id qwen3_asr_1_7b
cargo run -p voicelayer-cli -- dictation foreground-ptt --provider-id qwen3_asr_1_7b
vl config set foreground_ptt.provider_id qwen3_asr_1_7b

Implementation lives in python/voicelayer_worker/providers/qwen3_asr.py.

Provider Comparison

Backend Cold Load Warm Latency Languages Hardware
whisper_cpp (server) Seconds (mmapped ggml) ~0.65 s / call (base.en, CPU) English or multilingual (model dependent) CPU or GPU
mimo_v2_5_asr ~30 s into VRAM ~0.27 s / 3 s clip (RTX 5090, cu128) zh, en, yue, wuu, nan, Sichuanese, mixed CUDA, ~16 GB VRAM
qwen3_asr_1_7b Seconds (4.7 GB into VRAM) Sub-second / ≤15 s clip (CUDA bf16) 30 languages including Mandarin and Cantonese CUDA (~6 GB VRAM); CPU supported

Because crates/voicelayerd/src/worker/mod.rs keeps one persistent Python worker alive across requests, cold load for MiMo or Qwen3-ASR occurs only once per daemon lifetime unless the worker crashes or is restarted. Note that /v1/providers can also list experimental catalog entries such as voxtral_realtime that are not yet dispatchable; selecting one fails pre-flight validation.

Whisper Latency Benchmarks

Use the bundled benchmark scripts to compare one-shot whisper-cli cold-start latency against a warm whisper-server on your hardware:

# 1. Generate a deterministic 3-second silent WAV fixture (16 kHz mono PCM).
uv run python scripts/generate-silent-fixture.py

# 2a. Measure host whisper-cli cold start:
export VOICELAYER_WHISPER_MODEL_PATH=/abs/path/to/ggml-base.en.bin
RUNS=5 scripts/benchmark-whisper-cold-start.sh

# 2b. Or measure via Docker without installing whisper.cpp locally:
RUNS=5 scripts/benchmark-whisper-cold-start-docker.sh

# 3. Measure a running whisper-server and compare against the cold-start baseline:
COLD_START_SECONDS=0.8446 HOST=127.0.0.1 PORT=8188 \
  RUNS=10 WARMUP_RUNS=2 scripts/benchmark-whisper-warm-server.sh

On a CPU-only Ubuntu 24 reference host with ggml-base.en.bin, whisper-cli averaged ~0.84 s cold start (including Docker exec overhead), while a warm whisper-server saved ~0.26 s per call on real captures. Re-run the scripts for your own CPU/GPU and model size.
