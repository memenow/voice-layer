vl-desktop is the GUI shell that sits alongside vl and reaches the daemon through the same /v1 Unix socket. Unlike voicelayerd, it runs as an interactive user process (not a systemd user service), so its operator knobs live outside ~/.config/voicelayer/voicelayerd.env.

GUI panels

vl-desktop is an iced::daemon multi-window shell with a left navigation sidebar. The sidebar renders eight tabs in order: Dictation, Compose, Rewrite, Translate, Providers, Doctor, History, Settings.

Dictation

Start and stop streaming dictation with the "Start dictation · F9" button (or the global shortcut registered via the XDG portal when available). While a session is live the panel shows the session stage badge ("listening — speak now") and, on completion, the full transcript and detected language.

A second card ("Capture options") exposes per-session controls: ASR provider picker (populated from the daemon's registered providers), free-text input-language box (blank means auto-detect), segmentation picker (One-shot / Fixed window / VAD-gated), and a translate-to-English toggle. Below those controls a one-shot fixed-window capture button triggers POST /v1/dictation/capture for a bounded single-recording capture; it is disabled while a streaming session is in flight.

Compose, Rewrite, Translate

Each is a form that submits a request to the corresponding POST /v1 generative endpoint and yields a PreviewArtifact. After the preview appears an inject card lets you pick a target (InjectTarget), toggle auto-submit, and press "Plan injection" — which calls POST /v1/inject and returns an InjectionPlan (the daemon prepares the paste; it does not type into the focused application automatically). The resulting plan is shown inline.

  • Compose — spoken-style prompt, optional archetype (e.g. email, issue description), optional output language.
  • Rewrite — source text, restyle picker (e.g. more formal), optional output language.
  • Translate — source text, required target language.

Providers, Doctor, History

  • Providers — lists all daemon-registered ProviderDescriptor entries (id, kind, transport, local/remote badge). Refreshes on tab entry or via the Refresh button.
  • Doctor — daemon and worker health diagnostics: status, version, socket path, ASR configured/model, LLM configured/endpoint/reachable, global-shortcuts portal availability. Refreshes on tab entry or via the Re-probe button.
  • History — recent CaptureSession records from the daemon, showing session id prefix, mode, state, and trigger. Refreshes on demand.

Settings

Local, GUI-only preferences — there is no /v1 configuration route. These are session defaults seeded into each workflow; daemon-side configuration remains the CLI's domain.

  • Default output language (blank keeps the source language)
  • Default inject target
  • Recorder backend (Auto / PipeWire / ALSA)
  • One-shot capture window (5 / 8 / 12 / 20 / 30 seconds)

A separate "Appearance & accessibility" card exposes:

  • Glass opacity slider (0 % – 100 %). Persisted to desktop.toml and applied immediately.
  • Reduce Transparency toggle. Persisted to desktop.toml. GNOME exposes no system-level reduce-transparency signal (unlike macOS), so this stays a manual toggle rather than following the OS.
  • Read-only display of the live OS accessibility state — Increase Contrast and Reduce Motion — read from the XDG Settings portal and updated automatically. These are not editable here; they follow the system settings.

Capture HUD overlay

While the microphone is held (streaming dictation or a one-shot capture in flight), vl-desktop opens a second borderless transparent window: a small glass pill showing the capture state ("Listening — speak now", "Capturing · N s", etc.) with a synthetic animated waveform and, during streaming dictation, a "Stop · F9" button.

The HUD is best-effort always-on-top. On GNOME Wayland the compositor owns window placement — window::move_to is not supported and the always-on-top level hint is silently ignored, so the compositor decides where the pill lands. Position::Centered is the requested hint; wlroots and KWin compositors honor it. The layer-shell path that would force placement is not implemented.

The waveform animation is synthetic: the desktop client receives no microphone amplitude from the /v1 event stream, so the animation is time-driven rather than driven by real audio levels.

System tray

An optional StatusNotifierItem tray icon is compiled in when the tray cargo feature is enabled. It uses ksni (pure-Rust, no GTK / libappindicator dependency) and registers a menu with three items: Toggle dictation, Show VoiceLayer, and Quit VoiceLayer.

The tray is strictly best-effort. GNOME Shell has no built-in StatusNotifierHost; the tray icon is visible only when the user has installed the "AppIndicator and KStatusNotifierItem Support" GNOME Shell extension. When no host is reachable the shell logs once and runs on without a tray — all tray actions are also reachable from the main window and the CLI.

The tray holds no live session state; its menu items are stateless actions forwarded to the iced runtime as messages.

Liquid Glass visual language

vl-desktop uses a two-layer Liquid Glass rendering model:

  1. An opaque gradient backdrop (the graceful fallback tier — always visible).
  2. An animated wgpu/WGSL fragment shader painted over the backdrop: a drifting multi-stop gradient, frosted-glass grain, slow light blobs, a traveling specular sweep, a pointer-reactive highlight, and a vignette. This is the "glass" background the sidebar and content cards float above.

Platform honesty: a fragment shader cannot sample the framebuffer behind the window on GNOME Wayland, so there is no real desktop blur. The shader paints a self-contained rich background; glass cards lens this material, not the true desktop content underneath.

Graceful degradation is structural: if the GPU backend is unavailable iced falls back to the tiny-skia software renderer, where the custom shader primitive is a silent no-op. The opaque backdrop beneath it remains visible, giving the P1 appearance. No runtime detection is needed; the view always paints the backdrop first.

Accessibility knobs (see Settings above):

  • Glass opacity and Reduce Transparency are user-controlled and persisted to desktop.toml.
  • Increase Contrast and Reduce Motion are read live from the XDG Settings portal. When Reduce Motion is active the shell stops subscribing to per-frame ticks so the shader animation freezes (the material is still drawn; it just does not animate).

Launch

vl-desktop

Starting the daemon on demand: if vl-desktop cannot reach the socket it offers a "Start daemon" button that spawns voicelayerd and waits for readiness.

Environment variables

Variable Purpose Default
VOICELAYER_VL_BIN Absolute path to the vl binary that vl-desktop invokes when starting the daemon or issuing CLI fallbacks. $HOME/.local/bin/vl, then $PATH lookup
VOICELAYER_LOG tracing_subscriber env-filter for vl-desktop's logs. Accepts the usual target=level[,target=level]* syntax. vl_desktop=info

Both knobs are client-side only — the daemon does not read them. If you need to override VOICELAYER_VL_BIN or VOICELAYER_LOG persistently, set them in your shell profile, desktop entry, or launcher wrapper rather than the daemon env file. The coverage test in tests/python/test_env_example.py enforces this separation: these keys are listed in CLIENT_ONLY_ENV_VARS and intentionally excluded from systemd/voicelayerd.env.example.

Relationship to the daemon

  • VOICELAYER_SOCKET_PATH (documented in systemd.html) is consulted by vl-desktop through the same helper as the CLI; overriding it here makes vl-desktop talk to a non-default socket without touching the daemon unit.
  • vl-desktop consumes the same SSE stream (/v1/events/stream) the CLI does — portal-registered hotkeys, overlay state, and DictationFailureKind all flow through the shared event envelope.

System-wide hotkey

On startup vl-desktop registers the shortcut id voicelayer.dictation_toggle through org.freedesktop.portal.GlobalShortcuts. When the desktop session exposes the portal, the registered hotkey toggles the same dictation session the GUI start/stop buttons drive — there is no separate hotkey-only code path. When the portal is unavailable (the probe result surfaces in the window), vl-desktop falls back to the window-focused F9 binding inside the iced window.

The CLI tool vl does not consume the portal shortcut today; for terminal usage prefer vl dictation foreground-ptt, which handles press / release inside the controlling TTY's raw mode.
