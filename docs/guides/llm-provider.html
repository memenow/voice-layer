Recommended Baseline

Composition, rewrite, and translation workflows call any OpenAI-compatible chat completions endpoint. The local-first baseline is llama-server from llama.cpp, serving:

http://localhost:8080/v1/chat/completions

Example llama.cpp Startup

llama-server -m /path/to/model.gguf --port 8080

Or pull a GGUF model directly from Hugging Face during development:

llama-server -hf ggml-org/gemma-3-1b-it-GGUF --port 8080

Environment Variables

Configured for the daemon and forwarded to the Python worker:

VOICELAYER_LLM_ENDPOINT=http://127.0.0.1:8080
VOICELAYER_LLM_MODEL=gemma-3-1b-it
VOICELAYER_LLM_API_KEY=
VOICELAYER_LLM_TIMEOUT_SECONDS=60
VOICELAYER_LLM_AUTO_START=true
VOICELAYER_LLAMA_SERVER_BIN=llama-server
VOICELAYER_LLAMA_MODEL_PATH=/absolute/path/to/model.gguf
VOICELAYER_LLAMA_HF_REPO=
VOICELAYER_LLAMA_SERVER_ARGS=
VOICELAYER_LLAMA_LAUNCH_TIMEOUT_SECONDS=45
VOICELAYER_LLAMA_POLL_INTERVAL_SECONDS=0.5

VOICELAYER_LLM_ENDPOINT accepts any of these forms and normalizes them to /v1/chat/completions (probing /v1/models during health checks):

  • http://127.0.0.1:8080
  • http://127.0.0.1:8080/v1
  • http://127.0.0.1:8080/v1/chat/completions

When VOICELAYER_LLM_AUTO_START=true, the worker attempts to spawn llama-server automatically if:

  • the endpoint targets a loopback host
  • the endpoint is not yet reachable
  • either VOICELAYER_LLAMA_MODEL_PATH or VOICELAYER_LLAMA_HF_REPO is set

Autostart state and logs are written under:

$XDG_RUNTIME_DIR/voicelayer/providers

Example Source Workflow

export VOICELAYER_PROJECT_ROOT="$(pwd)"
export VOICELAYER_LLM_ENDPOINT="http://127.0.0.1:8080"
export VOICELAYER_LLM_MODEL="gemma-3-1b-it"
export VOICELAYER_LLM_AUTO_START="true"
export VOICELAYER_LLAMA_SERVER_BIN="llama-server"
export VOICELAYER_LLAMA_HF_REPO="ggml-org/gemma-3-1b-it-GGUF"

cargo run -p voicelayer-cli -- doctor
cargo run -p voicelayer-cli -- providers
cargo run -p voicelayer-cli -- preview compose "Write a concise status update for today's backend work."

User Service Configuration

When running under systemd on Linux, set these variables in ~/.config/voicelayer/voicelayerd.env before starting voicelayerd.service. See User Services for both Linux and macOS service configuration.
